# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Sessionary is a local-first session manager: it reads the on-disk history of Claude Code, OpenCode and Pi, indexes it, and serves a React UI (Hono server) for browsing, searching and resuming sessions. See `README.md` for features, config env vars and the HTTP API table.

## Commands

Package manager is pnpm; Node >= 22.13 (uses built-in `node:sqlite`, no native modules).

```sh
pnpm dev:server      # API on :4777 (tsx watch, --no-open)
pnpm dev:web         # Vite UI on :5173, proxies /api to :4777
pnpm typecheck       # tsc for server AND web (tsconfig in web/)
pnpm test            # node:test over test/*.test.ts
node --import tsx --test test/adapters.test.ts                      # single file
node --import tsx --test --test-name-pattern="<regex>" test/*.test.ts  # single test
pnpm build           # dist/ (tsup, server) + web-dist/ (vite, UI)
pnpm build:design    # regenerate the static design playground
```

No linter is configured. To develop against fake data, point `CLAUDE_CONFIG_DIR`, `XDG_DATA_HOME`, `PI_CODING_AGENT_DIR` and `SESSIONARY_HOME` at a temp directory.

## Architecture

- **Adapter contract** (`src/core/model.ts`, `src/adapters/*.ts`): all agent-specific code lives in adapters (list sources → load into the agent-neutral Session/Message/Block model, resume/continue commands, removal). Core, server and web must stay agent-neutral; add new agents by writing an adapter and registering it in `src/adapters/index.ts`.
- **Two stores with different guarantees**: `index-store` (`index.db`) is a derived, disposable SQLite index (summaries + FTS5 trigram full text) rebuilt by the incremental `scanner` using per-source fingerprints. `overlay.ts` (`overlay.db`) holds the user's own data (pins, hidden items, deletion records) and must never be derived or rebuilt. Full conversations are re-parsed from the agents' original files on open — the index is not the source of truth.
- **Live updates**: `watcher.ts` (debounced `fs.watch`) triggers rescans; `src/server/app.ts` pushes changes to the UI via server-sent events (`/api/events`). `src/cli.ts` wires first scan, watcher, fallback periodic scan and the server.
- **Safety model**: agents' files are read-only except the explicit delete-from-disk (moved to backup / `opencode export` first, `removal.ts`, `fsmove.ts`) and Continue-here (`runs.ts`, runs the agent's own headless CLI, read-only by default). Server binds loopback only, validates Host/Origin, and every POST needs the per-launch `x-sessionary-token`. Keep these guards intact when adding endpoints.
- **Nodes** (`src/core/nodes.ts`, `sync.ts`): other machines. Configs live in `overlay.db` (no secrets; ssh uses the user's own keys / `~/.ssh/config`). An `ssh` node needs nothing installed: `sync.ts` lists the node's history files with `find` over ssh and copies changed ones into a local mirror, in two stages — transcripts first (the node is online and indexed as soon as they are in, via `Mirror.apply`'s `afterTranscripts` callback), then the large databases in the background — using `rsync` (delta, compressed, atomic replace) when both ends have it, else `tar` (`<SESSIONARY_HOME>/nodes/<id>/home`, laid out like a home directory, tracked by `manifest.json`; SQLite copies are WAL-checkpointed). The usual adapters read that mirror via `adaptersFor(roots)` (adapters take a `Roots` — `localRoots()` for this machine, `mirrorRoots(dir)` for a node), indexed by a per-node `IndexStore` and served by a per-node in-process `createApp(..., { readOnly: true })` — so a node's API is the local API, but GET-only and without anything that touches this machine's disk (`LOCAL_ONLY` paths). A `url` node is a machine already running Sessionary, reached over HTTP with its token. Both are exposed at `/api/nodes/:id/proxy/api/...` (only `/api/*`, never `/api/token`). Resume of an ssh node's session = `ssh -t host <login shell> -lic 'cd <cwd> && <agent resume>'` (`sshTerminalCommand`). Everything user-supplied that reaches ssh's argv is validated in `parseNode`; the destination always follows `--`. Remote needs only ssh, GNU `find`, `tar`. Tests fake ssh with a script that runs the remote command locally (`test/sync.test.ts`). UI: everything under `#/nodes/` is routed by `web/src/NodesRouter.tsx` (list, `new`, `setup`, `<id>`, `<id>/sessions`, `<id>/search`, `<id>/s/<session id>`); a node's pages share `NodeShell` and read only through the proxy. Where only a session id is passed, a node's session is `node/<node id>/<session id>` (e.g. `api.imageUrl`).
- **Agents**: `claude-code`, `codex`, `opencode`, `pi`, `hermes`, `workbuddy`, `workbuddy-ai` (registry in `src/adapters/index.ts`). An adapter with `bin: ''` is a desktop app (WorkBuddy): nothing to find on PATH, no resume/new commands. Codex's rollouts and WorkBuddy's JSONL are parsed tolerantly; the shared WorkBuddy parser is `makeBuddy` (editions differ only by home: `~/.workbuddy`, `~/.workbuddy-ai`). Agent marks are in `web/src/AgentIcon.tsx` (Hermes, WorkBuddy images in `web/public/agents/`).
- **Machines → agents → projects → sessions**: the product's information architecture. A *machine* is this computer (`local`) or a node; `GET /api/machines` lists them, and every machine answers the same session API (this computer at `/api/…`, a node at `/api/nodes/:id/proxy/api/…`; `makeApi(machineBase(id))` in `web/src/api.ts`). Pages are written once and given the open machine through `MachineProvider` (`useMachine()` / `useApi()` in `web/src/machines.tsx`). A node's view is read-only (no continue/delete/open, no git or file-tree routes) except for Sessionary-owned decisions (pin, rename, hide), which live in `overlay.db` under a `node:<id>/` prefix (`OverlayStore.scoped`). Which agents are installed (`GET /api/machines/:id/agents`) is remembered in `probe-cache.json` (`src/core/probecache.ts`): answers come from memory at once and refresh in the background when older than `SESSIONARY_PROBE_FRESH_MS` (60 s), `?refresh=1` forces a look; a node's login-shell PATH is kept 6 h, a program's version is re-read only when its file's `mtime:size` changes, and nodes/this computer are probed once at startup / when a node comes online. `src/core/system.ts` runs one shell script (this computer or over `sh -c` on a node) for CPU/memory/disk/network and per-process CPU (two samples 0.5 s apart, from /proc) and agent versions. `src/core/terminals.ts` runs interactive terminals the page attaches to over SSE (`/api/terminals/:id/stream`, input by POST): this computer through a Python `pty` helper (no native modules; falls back to `script`, which cannot resize), a node through `ssh -tt` under the same helper, so the page's size (xterm fit) is forwarded all the way (`POST /api/terminals/:id/resize` writes `R cols rows` to the helper's fourth pipe); a terminal keeps running when the page leaves.
- **Notices** (`src/core/notifier.ts`): the server notices what is worth an interruption — an agent started from an app terminal (`kind` resume/new) that printed a long, heavy burst and then went quiet (`agent.idle`, tuned by `SESSIONARY_NOTIFY_QUIET_MS`/`_BURST_MS`/`_MIN_BYTES`), such an agent exiting by itself (not when stopped from the app), a node that stays in `error` for `SESSIONARY_NOTIFY_DOWN_MS` (and coming back), a large (>50 MB) node copy finishing — and streams codes + facts over `GET /api/notifications` (SSE, token in the query, nothing replayed). The page (`web/src/notify.tsx`) decides whether to interrupt: master/per-type switches and a pause (persisted), no notice for what is being looked at, per-key cooldowns, one interruption per 8 s with the rest merged, desktop notifications only when the page is in the background and only for loud codes. A closed page hears nothing. Unread items badge the nav (bell, Terminal, machine switcher) and the page title.
- **Chats** (`src/core/chat/`): a real conversation with an agent over its own bidirectional protocol, not one headless run per message. `types.ts` is the agent-neutral event model (`text`, `thinking`, `tool` upserts by id, `approval`, `question`, `turn`, `info`…); one `ChatDriver` per protocol translates into it: `claude.ts` (`claude -p --input-format stream-json`, `can_use_tool` control requests), `codex.ts` (`codex app-server` JSON-RPC; approval policy + sandbox are the "modes"), `acp.ts` (Agent Client Protocol — `opencode acp`, `hermes acp`), `pi.ts` (`pi --mode rpc`). `manager.ts` (`Chats`) keeps the processes alive on the server (one per session, max `SESSIONARY_CHAT_MAX`, idle ones with no page open close after `SESSIONARY_CHAT_IDLE_MS`), numbers events and compacts the log (finished text replaces its deltas, a tool keeps one entry; readers filter by `seq`, array order is logical order), and derives `state` (starting/idle/working/waiting/closed). An ssh node's chat runs the agent over `ssh` without a tty (`ssh.ts`, login shell for PATH) — nothing installed there; chats are served by the main app (`/api/chats*`, not proxied) with `machine` in the request. Resuming passes the agent's own id (the last arg of its resume command; Pi uses its uuid on nodes). The page follows `GET /api/chats/:id/events` (SSE with `Last-Event-ID` replay); `web/src/chat.ts` folds events into a view, `LiveThread` draws the turns the agent's own history does not yet contain (`pendingTurns`), `ChatComposer` is the box (model/mode/effort pickers, `/` commands, steer, stop). WorkBuddy has no CLI so it keeps only the old headless "Continue here" (`runs.ts`), which is also the fallback when a chat cannot start. Tests: `test/chat.test.ts` uses a fake stream-json agent; `SESSIONARY_NOTIFY_CHAT_MIN_MS` sets how long a turn must take to notify on its end.
- **Model Control** (`src/core/control/`, design notes in `docs/model-control.md`): `Agent → Routing → Model → Provider`, this computer only. `store.ts` is `control.db` (providers with per-protocol base URLs and keys — the only secrets Sessionary keeps, file `0600`, keys masked to the page, `env:NAME` allowed —, routing groups `group/<id>` whose members are `<provider>/<model>`, agent bindings, the persistent gateway key, usage rows). `gateway.ts` is a Hono sub-app at `/gateway` on the same port (own key, `Bearer`/`x-api-key`, suffix `.<agent>` names the caller; refuses a non-loopback `Origin`): same-protocol passthrough only (`anthropic` `/v1/messages`, `chat` `/v1/chat/completions`, `responses` `/v1/responses`), members whose provider lacks that protocol are skipped, failover only before the first byte, failures rest a member by cause (`restFor`; 400/413/422 rest nobody and are passed back), a model the gateway does not know falls back to the caller's binding; usage is tapped from the stream (`usageOf`) and decisions are pushed as `route` events on `/api/events`. **Agents' config files are never written**: a binding reaches an agent only through how Sessionary starts it (`launchProfile` in `agents.ts`: Claude Code env + `--model`, Codex `-c model_provider…`, OpenCode `OPENCODE_CONFIG_CONTENT`; Pi/Hermes get a snippet only), applied in `startTerminal` and via `ChatsOptions.launchFor`; local machine only. `agentModelState` only reads what an agent runs on by itself (and detects Magpie at `:3425`). `createApp` keeps an in-memory `ControlStore` unless `opts.control` is given (the CLI passes the real one). UI: `web/src/control.tsx` (state provider, `ModelPicker`, marks), `ModelsPage`, `RoutingPage`, `GatewayPage`, `UsagePage`; routes `#/models[/<provider>][?add=1]`, `#/routing[/<group>]`, `#/gateway`, `#/usage[?src=history]`; the sidebar has Workspace / Model Control / System sections. Tests: `test/control.test.ts` (fake upstreams over `node:http`).
- **Web** (`web/`, Vite + React 19): routes are hash URLs parsed in `web/src/route.ts` (`#/`, `#/machines`, `#/nodes[?add|edit]`, `#/m/<machine>[/projects|sessions|terminal|monitor|trash]`, `#/m/<machine>/a/<agent>[?p=]`, `#/m/<machine>/s/<session>`, `#/m/<machine>/c/<chat>` for a chat with no session yet); `App.tsx` is only the window (nav, overlays, inspector slot) and the pages are `HomePage`, `MachinesPage`, `MachinePage` (+ `MachineTabs`, `TerminalTab`, `MonitorTab`), `AgentPage`, `SessionPage` (wraps `Conversation`), `NodesPage`. Actions on a session are in `sessionActions.tsx`. `web/src/styles.css` holds the design tokens and themes; every UI string goes through `t()` with translations in `locales.ts` (en, zh-CN, zh-TW, ja) — `test/i18n.test.ts` fails on any missing translation. Static assets (favicon, logo tile) are in `web/public/`.
- `design/playground/` is a static design source (`src.html`) built by `build.mjs`; separate from the app.

`dist/` and `web-dist/` are build outputs.
